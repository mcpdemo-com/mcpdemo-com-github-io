Slack MCP Integration with Claude AI

Your team's knowledge lives in Slack. Learn how Model Context Protocol (MCP) lets Claude search messages, list channels, and surface workspace context — all through a natural language conversation.

Key Takeaways

  • Model Context Protocol (MCP) is an open standard that lets Claude AI connect directly to Slack, reading live workspace data without manual copy-paste.
  • Through MCP, Claude can list channels, read message history, and surface relevant conversations in real time — all from a single natural language interface.
  • A Slack bot app with channels:read and channels:history scopes is all the authentication required — no OAuth redirect flow, no per-user login.
  • Teams use the Slack MCP connection to find past decisions, audit channel activity, and answer questions that would otherwise require manual scrolling through hundreds of messages.
  • The bot token stays server-side in a Cloudflare Worker — your Slack data never passes through Anthropic or any third-party storage.

What MCP Actually Is (Plain English Version)

Model Context Protocol (MCP) is an open communication standard, created by Anthropic, that defines how AI models like Claude connect to external data sources and tools. Think of it as a universal plug — instead of building a custom integration every time you want Claude to talk to a new service, MCP provides a shared language both sides already speak.

Before MCP existed, connecting an AI assistant to Slack meant writing custom API wrappers, parsing webhook payloads, and wiring up message formatting by hand. MCP standardizes that entire handshake. Claude discovers what tools are available, calls them with structured parameters, and receives structured results — without any bespoke glue code on your end.

An MCP server is a lightweight service that sits between Claude and your data source. For Slack, it exposes tools like list_channels and get_channel_history that Claude can call mid-conversation. Claude doesn't need to understand Slack's API internals — it just needs to know which tools exist and what parameters they accept. The MCP server handles the translation.

Why Claude Specifically?

Claude is Anthropic's AI assistant, and it treats MCP as a first-class feature. Tool calls are reliable across long conversations, context is preserved as Claude chains multiple calls together, and Claude can reason over the results it gets back — not just display them. Ask Claude "which channel had the most discussion about the product launch last week?" and it will call the right tools in sequence, aggregate the results, and give you a useful answer.

How the Slack MCP Connection Works

The Slack MCP connection works by running a server-side proxy — in this demo, a Cloudflare Worker — that holds a Slack bot token and makes calls to the Slack Web API on Claude's behalf. Claude communicates with that Worker using structured tool calls, and the Worker translates those into real Slack API requests.

Here's the flow: you ask Claude something like "show me the last 10 messages in #general." Claude identifies the right tool call, sends the request to the Worker at api.mcpdemo.com/proxy/slack, and the Worker calls conversations.history on the Slack API using your bot token. Slack returns the messages; the Worker formats them; Claude presents the results in natural language. The round-trip takes a few seconds.

Setting Up the Slack MCP Connection

Connecting Claude to Slack via MCP involves three steps: creating a Slack bot app, configuring your MCP server or proxy, and pointing Claude at that server. You don't need to be a senior developer — if you're comfortable with API keys and a terminal, you can complete this in under 15 minutes.

Step 1 — Create a Slack Bot App

Go to api.slack.com/apps and create a new app from scratch. Under OAuth & Permissions, add bot token scopes for the operations you need. For read-only channel access: channels:read and channels:history. Install the app to your workspace and copy the Bot User OAuth Token — it starts with xoxb-. That token is the only credential your MCP server needs.

Step 2 — Configure Your MCP Server

The Slack Web API accepts bearer token authentication directly, which means any server-side proxy can act as an MCP layer. The demo on this page uses a Cloudflare Worker that holds the bot token as a Worker Secret and proxies Claude's tool calls to the Slack API. You can also self-host using any of several open-source Slack MCP server packages available on GitHub — most support stdio transport for local use or HTTP transport for hosted deployments.

The Worker pattern used here is ideal for shared demos and team tools: the token never reaches the browser, rate limits are enforced server-side, and the Worker can be updated without touching Claude's configuration.

Step 3 — Connect Claude to Your MCP Server

The Anthropic Messages API supports MCP servers via the mcp_servers parameter. Pass your Worker URL and Claude automatically discovers the tools the server exposes:

const response = await fetch("https://api.anthropic.com/v1/messages", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-api-key": YOUR_ANTHROPIC_API_KEY,
    "anthropic-version": "2023-06-01",
    "anthropic-beta": "mcp-client-2025-04-04"
  },
  body: JSON.stringify({
    model: "claude-sonnet-4-20250514",
    max_tokens: 1024,
    messages: [{ role: "user", content: "List all channels in the workspace" }],
    mcp_servers: [{
      type: "url",
      url: "https://your-slack-mcp-server.example.com/mcp",
      name: "slack-mcp",
      authorization_token: "your-server-token"
    }]
  })
});

Real-World Use Cases

Finding Past Decisions Without Scrolling

Engineering and product teams make dozens of decisions in Slack every week — and then spend hours later trying to find them. With Claude connected via MCP, you can ask "what did the team decide about the API rate limit strategy?" and Claude will search the relevant channels, surface the thread, and summarize the outcome. No manual scrolling, no keyword guessing in Slack's own search UI.

Onboarding New Team Members

New hires face a wall of context when they join a Slack workspace. Claude with MCP can answer onboarding questions directly from channel history: "What's the current deployment process?" or "What tools does the team use for monitoring?" The answers exist somewhere in Slack already — MCP gives Claude the ability to find and surface them.

Standups and Activity Summaries

Managers and team leads who want a quick pulse on what happened across channels can ask Claude to summarize recent activity. "Summarize the last 24 hours in #product and #eng" is a single prompt that would otherwise require manually reading two or more channels. Claude reads the history, filters the noise, and delivers a concise summary.

Audit and Compliance Review

Teams with compliance requirements sometimes need to review channel activity for specific time periods or topics. Claude's MCP connection lets authorized reviewers query channel history programmatically through natural language — far faster than manual review, and without granting direct Slack admin access to every reviewer.

Security and Permissions

Your Slack bot token is only as permissive as the scopes you grant it. A token with channels:read and channels:history can read public channel messages — it cannot post messages, join private channels, or access direct messages. You control the scope at the app level in Slack's developer dashboard, and those limits are enforced by Slack's API itself.

In the Worker pattern used by this demo, the bot token is stored as a Cloudflare Worker Secret — it never appears in your HTML, never passes through the browser, and is not visible to Anthropic. Claude calls the Worker; the Worker calls Slack; your token stays server-side throughout.

For production deployments, Slack also supports token rotation, IP allowlists, and workspace admin oversight of installed apps — all of which layer on top of your MCP integration without requiring any changes to how Claude connects.
